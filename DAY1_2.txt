We can discard any output of a script that we use by redirecting to /dev/null.

command > /dev/null 2>&1


 0 representing stdin, 1 representing stdout, and 2 representing stderr.

> stdout here
2> stderr here
< stdin from here

&> file  - file gets stdout & stderr from command, file is created or overwritten

2>&1 redirects standard error ( 2 ) to standard output ( 1 )


Notice the 2>&1 at the end. We redirect stderr(2) to stdout(1). 
We use &1 to mention to the shell that the destination file is a file descriptor and not a file name.
So if we use 2>1, we will only redirect stderr to a file called 1. This is not what we want!

find /path/to/search -type f -name "*.txt" -exec <command> {} \;


-mtime: This option is used to search for files based on the modification time (i.e., the time the file's contents were last modified).
+5: This specifies that you want to find files modified more than 5 days ago. The + sign means "greater than," so it looks for files that haven't been modified in the last 5 days.

/path/to/search: The directory where you want to search.
-type f: This restricts the search to files (replace with -type d for directories).
-name "*.txt": Search for files matching a specific pattern.
-exec: This option specifies the command to run on each result found by find.
{}: A placeholder for the file path returned by find. For each file found, find will replace {} with the full path of the file.
\;: Terminates the -exec command. The \; tells find that the command ends there. It must be escaped (\) to prevent the shell from interpreting it.



The -exec option allows you to perform an action (such as delete, copy, or move) on each file that the find command locates.
{} is a placeholder that represents the file found.
\; or + ends the command and specifies whether the command should run on each file individually (\;) or all at once (+).

# Return COmmand -
Functions return when there are no more statements or 
When a return statement is executed

The return command is used to exit a function and provide an exit status.
This status can be any integer, and by convention, a return value of 0 indicates success, while any non-zero value indicates failure or some specific error.

function myfunc {
	echo starting
	return
	echo this will not be executed 
}	

# Exit Command

If a function returns 0, it indicates that the function completed successfully.
If a function returns a non-zero value, it indicates an error or some specific condition the script is designed to handle.

return is used only in functions and terminates the function execution.
exit terminates the entire script or shell session, not just a function.

*Important Notes:
If you use return outside a function, you'll get an error, as return is only valid within functions.
In normal shell commands (outside of functions), you would use exit to terminate the script with a status code.


## exec 19<data_file in shell script

exec is a built-in command that can manipulate file descriptors.
19 is the file descriptor number. You can choose any number that isn't already in use (standard file descriptors are 0 for stdin, 1 for stdout, and 2 for stderr).
<data_file indicates that the file is being opened for reading.

After you're done with the file, it's a good practice to close the file descriptor using exec 19<&-.

## lsof -p $$ - COMMAND

lsof: This stands for "list open files." It is a utility that displays information about files opened by processes.

-p: This option specifies that you want to filter the output to show only the files opened by a particular process.

$$: This is a special variable in shell scripting that holds the process ID (PID) of the currently executing shell. By using $$, you are effectively telling lsof to list the open files for the current shell process.
